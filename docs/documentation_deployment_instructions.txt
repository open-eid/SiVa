Our documentation is written using [MkDocs](https://www.mkdocs.org/) static documentation site generator with [Material theme](https://squidfunk.github.io/mkdocs-material/) and [Markdown](https://daringfireball.net/projects/markdown/).

System requirements
-------------------

* **Python 3** (3.10 or newer; 3.14 is what the pinned versions were last built with)
* **pip** and **venv** - both ship with Python 3
* **Text editor** - to edit the Markdown files

Installing required software
-----------------

The Python packages that build the site are pinned to exact versions in `docs/requirements.txt`:
the full set MkDocs and the Material theme resolve to, generated from the two top-level pins in
`docs/requirements.in` (the Markdown extensions `mkdocs.yml` names ship with Python-Markdown).
Install them into a virtual environment, on any operating system:

```bash
python3 -m venv .venv
.venv/bin/pip install -r docs/requirements.txt
```

On Windows the executables are under `.venv\Scripts\` instead of `.venv/bin/`.

Upgrading a pinned version: change `docs/requirements.in`, install it into a fresh virtual
environment (`pip install -r docs/requirements.in`), run the strict build below, then regenerate
`docs/requirements.txt` from that environment with `pip freeze` under the file's header; the site
must build without warnings before the bump is committed.

Editing content
---------------

1.  Edit the Markdown files inside the `docs` directory
2.  Preview your changes with `.venv/bin/mkdocs serve` and navigate to <http://localhost:8000>
3.  Build the site exactly as it will be published: `.venv/bin/mkdocs build --strict` (every warning, such
    as a broken link or a `nav` entry without a file, fails the build; fix it before committing)
4.  Commit and push your changes

Deploying the site
------------------

`mkdocs build --strict` writes the complete static site to `site/`. The publishing step is the
maintainers': how that directory reaches the published documentation (a pages branch, a CI job, a web
server) is theirs to run and is not described here.
